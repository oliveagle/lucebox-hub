## 结论

1. **Forward 步骤是绝对瓶颈**：在 8K 占 96.7%，在 32K 占 98.5%。优化空间主要在 sparse_flash_forward_bf16 内核。

2. **性能随序列长度扩展性尚可**：从 2K 到 32K 总时间增长约 170x（理论线性是 16x），Forward 步骤增长约 175x，接近 O(S^1.5) 的稀疏注意力复杂度预期。

3. **Mean K 和 Score 计算开销很低**：两者合计不超过总时间的 4%，rocWMMA GEMM 在 gfx1151 上表现良好。

4. **Block Select 非常高效**：GPU kernel 实现，所有长度下均 < 0.2ms。

5. **合并后性能稳定**：gfx1151-01 的优化与 gfx1151 的 GPU sync 优化兼容，无性能回归。

## 下一步优化方向

1. **优化 sparse_flash_forward_bf16**：当前占 96%+ 时间，是最大优化目标
2. **端到端 decode 测试**：使用 GGUF 模型进行完整推理流程测试
3. **测试更大上下文**：64K/128K 场景下性能衰减曲线
4. **对比 CUDA 平台性能**：确认 rocWMMA 与 cuBLAS WMMA 的差距
