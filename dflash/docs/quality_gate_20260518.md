# DFlash 质量门禁配置

**日期**: 2026-05-18

## 背景

在之前的开发过程中发现了一个严重问题：所有 "Qwen3.6 接受率提升" 任务被自动关闭，但实际上没有任何训练数据收集、模型训练或测试被执行。关闭理由是"实现完成"，但实际只是脚本准备就绪，并未执行。

## 质量门禁配置

配置文件：`.beads/policy.yaml`

### 当前规则

1. **require_close_reason**: 关闭任务必须提供关闭理由
2. **require_acceptance_criteria_satisfied**: 接受率/训练/测试相关任务必须满足验收标准

### 禁止的关闭理由

- "实现完成"（无实际产出）
- "代码完成"（无测试）
- "TODO"、"FIXME"、"placeholder"
- "待实现"、"未完成"、"计划中"

### 要求的证据

- **接受率任务**: 实测数据、接受率 >= 60%、AL >= 8.0、tok/s >= 60
- **训练任务**: 模型文件产出（safetensors/gguf）
- **测试任务**: 测试结果（tok/s、AL、接受率）
- **数据收集任务**: 数据文件路径

## 防止再次发生

### 规则 1: Epic 关闭前检查

所有子任务必须实际完成，不能只是"代码准备就绪"。

### 规则 2: Story 关闭前检查

所有子任务必须实际完成，必须有可验证的产出。

### 规则 3: P0/P1 任务关闭

必须有关键证据（实测数据、测试报告）。
